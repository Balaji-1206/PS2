# Dual Verification & Provenance Layers — Technical Design Specification (v1.0)

**Date**: 2026-09-25  
**Components**: Dual Verification & Provenance (Governed Content Transformation Platform)  
**Status**: Implementation Specification  

---

## 1. Dual Verification Layer (`dual_verification/`)

### Purpose
To safeguard against hallucinations and unauthorized claims by running every claim generated by `qwen3:8b` through dual, independent verification gates against the extracted source document blocks.

### Architecture
1. **Primary Verifier (`PrimaryVerifier`)**:
   - Queries `qwen3:8b` with a specialized Natural Language Inference (NLI) prompt.
   - Evaluates whether the cited source block strictly entails, contradicts, or fails to support the claim statement.
2. **Secondary Verifier (`SecondaryVerifier`)**:
   - Deterministic rule and token-level gate.
   - Validates citation pointer existence in extraction storage.
   - Cross-checks critical entity tokens (numbers, dates, currency, percentages) between claim and source text.
3. **Arbiter (`VerificationArbiter`)**:
   - Combines Primary & Secondary verdicts into a consensus verdict (`VERIFIED`, `CONTRADICTED`, `UNSUPPORTED`).
   - Assigns a confidence score and flags discrepancies.
4. **Storage & REST API**:
   - Persists artifacts in `dual_verification/storage/verifications/{verification_id}.json`.
   - `POST /verify`: Accepts `generation_id` (or direct claims + document), runs verification.
   - `GET /verify/{verification_id}`: Retrieves verification report.

## 2. Provenance Layer (`provenance/`)

### Purpose
To provide an end-to-end, tamper-evident audit trail and lineage graph connecting the original source document through extraction, transformation, and verification to the final output.

### Lineage Graph Schema
```mermaid
graph LR
    A[Source Document Node] --> B[Extraction Node: blocks & bbox]
    B --> C[Generation Node: prompt & qwen3:8b]
    C --> D[Verification Node: dual check & verdicts]
    D --> E[Governed Artifact Manifest: cryptographic hash & lineage]
```

### Key Models
- `SourceNode`: Document ID, filename, source type, SHA-256 hash, ingest timestamp.
- `ExtractionNode`: Extracted block pointers, hierarchy summary.
- `GenerationNode`: Generation ID, model version, instruction, claim count.
- `VerificationNode`: Verification ID, overall status, pass/fail ratios.
- `ProvenanceRecord`: Complete immutable lineage manifest with citation map.

### REST API
- `POST /provenance/build`: Assembles the full lineage graph from `generation_id` or `verification_id`.
- `GET /provenance/{provenance_id}`: Returns the complete audit record.
- `GET /provenance/lineage/{document_id}`: Traces historical transformation lineage for a document.
